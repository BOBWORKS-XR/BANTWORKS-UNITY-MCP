# BANTWORKS MCP Audit - 2026-07-13

## System Map

The installed Windows application is a Tauri launcher. It manages channels in
`%APPDATA%\banter-mcp\launcher-config.json`, writes the Banter entry into Claude
and Codex configuration, and copies the Unity bridge into a selected project.
It does not host the MCP protocol.

The MCP server is `dist/index.js`, built from `src/`. It talks to Unity through
the selected project's `.bantworks-mcp` directory:

- `commands/*.json`: MCP to Unity requests.
- `state/*.json`: Unity to MCP scene state, logs, and import state.
- `state/command-results/*.json`: Unity command acknowledgements.

The Unity side is `unity-extension/Editor/BanterMCPBridge.cs`. It is an Editor
extension, so it is not included in player builds.

## Client Compatibility

The server uses the standard stdio MCP transport. The launcher and `setup.ps1`
write the same `banter` server entry to Claude Code and Codex configuration,
using the selected Unity project as `UNITY_PROJECT_PATH`. Codex configuration
is stored at `~/.codex/config.toml` under `[mcp_servers.banter]`.

The bridge and protocol are project-neutral. They provide Unity editor state
and scene operations, not game-specific gameplay behavior.

## Banter Visual Scripting Knowledge

The MCP includes Banter-specific Visual Scripting knowledge rather than relying
only on generic Unity graph syntax. The bundled references cover 163 unique
Banter node types, including 162 exact custom node types extracted from a real
`AllCustomNodes.asset`. The custom catalogue records each node's full type,
category, serialized defaults, sample GUID, and event metadata.

The supplied Unity Visual Scripting JSON manual v2.2 is embedded as
`banter://unity-vs-json-manual` behind higher-priority compatibility errata
derived from Unity 2022 and Unity 6 assets. It documents the Unity YAML wrapper,
graph JSON structure, real GUIDs, node IDs, connections, variables, port names,
Banter sandbox limits, common failures, and examples. `generate_vs_graph` uses
the captured custom-node defaults and canonical `graph.elements` layout.
`validate_vs_graph` checks current and legacy layouts, duplicate/dangling IDs,
and observed connection-version behavior. `write_vs_graph` validates again
before writing the native asset and importer metadata.

`get_banter_sdk_info` reports the selected project's requested Banter package,
resolved source, git revision or package-cache identity, and live C# class
coverage against the embedded catalogues. The package version alone is not
treated as provenance because observed git and registry builds differ.

This is generation and validation knowledge, not a guarantee that every graph
will run under every Unity and Banter SDK version. Graphs still need an import
and runtime test in the target project.

## Corrected In This Pass

1. **Partial JSON handoff:** command and server-generated asset writes now use
   temp-file publish semantics. Unity state exports use the same pattern with a
   short Windows sharing retry.
2. **False mutation success:** Unity now writes a command result for each
   command. The MCP waits briefly for that result and returns a Unity error for
   failures such as an object that does not exist. Failed command files are
   archived under `.bantworks-mcp/commands/failed` instead of being retried
   forever.
3. **Ambiguous scene targeting:** bridge mutations now resolve paths across
   active and inactive objects in the active scene. Duplicate hierarchy paths
   are rejected rather than applying an operation to an arbitrary object.
4. **Project escape writes:** `write_webroot_js` and `write_vs_graph` reject
   paths that would write outside `Assets/WebRoot` or `Assets`.
5. **Launcher safety:** malformed Claude config now produces an error rather
   than replacing the file with an empty config. Launcher writes are published
   atomically, and installing a bridge backs up the previous bridge outside
   `Assets`.
6. **Version drift:** package, MCP protocol, Tauri manifest, Cargo package, and
   launcher footer now agree on `1.4.0`.
7. **Dependency risk:** upgraded `@modelcontextprotocol/sdk` from `1.25.1` to
   `1.29.0`, removed the unused `uuid` dependency in favor of Node's built-in
   generator, and applied the compatible `ajv` / `fast-uri` security updates.
8. **Concurrent bridge responses:** state export requests now use unique,
   atomically published command files, and bounds queries write to a
   command-specific result file instead of a shared `bounds-result.json`.
9. **Visual Scripting serialization:** generated graphs now use canonical
   `graph.elements`, explicit ScriptGraphAsset identity, and
   `NativeFormatImporter`. Existing MCP-authored `MonoImporter` metadata is
   migrated without changing its Unity GUID.
10. **Banter catalogue drift:** corrected the stale component count, added the
    five SDK 3.2.2 scene components that were absent, distinguished the
    `BanterObjectId` runtime helper, recorded source hashes, and added selected
    project source-coverage diagnostics.

## Verified

- `npm run build` completed successfully.
- `cargo check` completed successfully.
- `npm audit` reported zero known vulnerabilities after the dependency update.
- Unity 6000.3.10f1 compiled the bridge successfully in a test Unity project.
- A live `get_object_bounds` MCP request returned bounds for `Level`.
- A live mutation request for a nonexistent object returned the explicit Unity
  failure instead of reporting success.
- Traversal attempts for WebRoot filename, graph folder, and graph name were
  rejected in an isolated filesystem test; a valid JavaScript file was written
  in the expected project folder.
- `npm test` covers bridge status, project routing, typed values, package
  provenance, Visual Scripting generation/validation/writes, metadata
  migration, Test Runner state, and tool schemas.
- Burger Clone's real `FollowAnimation.asset` validates with 14 nodes and 21
  connections without the previous false errors for omitted connection
  versions or an unreferenced node ID.
- A canonical generated graph was written with native Unity metadata, imported
  synchronously, and deserialized through the full MCP handler in an isolated
  Unity 2022.3.39f1 project with Visual Scripting 1.9.4. Unity resolved one
  `Unity.VisualScripting.Start` element with no missing or unknown elements.
- In an isolated Unity 6000.3.2f1 project with Banter SDK 3.2.2 and Visual
  Scripting 1.9.9, a generated `Banter.VisualScripting.OnGrab` graph imported
  with no missing elements and passed Banter's public `CheckVsNodes()` scan.
- A disposable non-allow-listed custom Unit also imported successfully, then
  failed Banter validation with the exact forbidden type returned in structured
  MCP diagnostics. A project without Banter returned an explicit
  validator-unavailable result while the generic bridge continued to compile.
- The observed Banter 3.2.2 package fingerprint declares Unity 2022.3.39f1 but
  references Unity 6 `PhysicsMaterial` APIs and failed compilation in a clean
  Unity 2022.3.39f1 fixture. The same package compiled in Unity 6000.3.2f1;
  package metadata alone is therefore not treated as compatibility proof.

## Remaining Work

### High Value

Status update (2026-07-14): stable `GlobalObjectId` selectors, typed inspector
writes, and preflighted transactional batches are implemented and covered by
the current protocol documentation and tests.

### Important Limits

- Unity deserialization and Banter's allow-list validator are now separate,
  structured gates. Neither proves runtime behavior, and the current Unity/Banter
  fixture matrix is manually exercised rather than committed as automated CI.
- State export only covers the active scene and stops hierarchy recursion at
  depth 10. Additive scenes and deeper hierarchies are not represented fully.
- Prefab scanning is synchronous and exports at most 500 prefabs per category.
  Large projects should move to incremental scanning and expose paging.
- Import status is editor-global rather than a reliable per-asset compiler
  diagnostic. It should be backed by AssetPostprocessor events and structured
  compilation diagnostics.
- Resolved 2026-07-14: the launcher now discovers a versioned bundled server
  and bridge, migrates only missing legacy defaults, and preserves deliberate
  custom server paths. Standalone and Tauri distributions no longer depend on
  a machine-specific source checkout.
