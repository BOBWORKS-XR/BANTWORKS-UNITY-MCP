# BANTWORKS MCP Audit - 2026-07-13

## System Map

The installed Windows application is a Tauri launcher. It manages channels in
`%APPDATA%\banter-mcp\launcher-config.json`, writes the Banter entry into Claude
and Codex configuration, and copies the Unity bridge into a selected project.
It does not host the MCP protocol.

The MCP server is `dist/index.js`, built from `src/`. It talks to Unity through
the selected project's `.bantworks-mcp` directory:

- `commands/*.json`: MCP to Unity requests.
- `state/*.json`: Unity to MCP scene state, logs, and import state.
- `state/command-results/*.json`: Unity command acknowledgements.

The Unity side is `unity-extension/Editor/BanterMCPBridge.cs`. It is an Editor
extension, so it is not included in player builds.

## Client Compatibility

The server uses the standard stdio MCP transport. The launcher and `setup.ps1`
write the same `banter` server entry to Claude Code and Codex configuration,
using the selected Unity project as `UNITY_PROJECT_PATH`. Codex configuration
is stored at `~/.codex/config.toml` under `[mcp_servers.banter]`.

The bridge and protocol are project-neutral. They provide Unity editor state
and scene operations, not game-specific gameplay behavior.

## Corrected In This Pass

1. **Partial JSON handoff:** command and server-generated asset writes now use
   temp-file publish semantics. Unity state exports use the same pattern with a
   short Windows sharing retry.
2. **False mutation success:** Unity now writes a command result for each
   command. The MCP waits briefly for that result and returns a Unity error for
   failures such as an object that does not exist. Failed command files are
   archived under `.bantworks-mcp/commands/failed` instead of being retried
   forever.
3. **Ambiguous scene targeting:** bridge mutations now resolve paths across
   active and inactive objects in the active scene. Duplicate hierarchy paths
   are rejected rather than applying an operation to an arbitrary object.
4. **Project escape writes:** `write_webroot_js` and `write_vs_graph` reject
   paths that would write outside `Assets/WebRoot` or `Assets`.
5. **Launcher safety:** malformed Claude config now produces an error rather
   than replacing the file with an empty config. Launcher writes are published
   atomically, and installing a bridge backs up the previous bridge outside
   `Assets`.
6. **Version drift:** package, MCP protocol, Tauri manifest, Cargo package, and
   launcher footer now agree on `1.4.0`.
7. **Dependency risk:** upgraded `@modelcontextprotocol/sdk` from `1.25.1` to
   `1.29.0`, removed the unused `uuid` dependency in favor of Node's built-in
   generator, and applied the compatible `ajv` / `fast-uri` security updates.

## Verified

- `npm run build` completed successfully.
- `cargo check` completed successfully.
- `npm audit` reported zero known vulnerabilities after the dependency update.
- Unity 6000.3.10f1 compiled the bridge successfully in a test Unity project.
- A live `get_object_bounds` MCP request returned bounds for `Level`.
- A live mutation request for a nonexistent object returned the explicit Unity
  failure instead of reporting success.
- Traversal attempts for WebRoot filename, graph folder, and graph name were
  rejected in an isolated filesystem test; a valid JavaScript file was written
  in the expected project folder.

## Remaining Work

### High Value

- **Stable object references:** hierarchy paths are human-readable but cannot
  identify duplicate siblings. The current bridge fails closed. A future
  protocol revision should export and accept `GlobalObjectId` values alongside
  paths.
- **Typed inspector writes:** `set_component_property` still takes a string and
  only supports a subset of `SerializedPropertyType`. Replace it with a typed
  JSON value contract and per-type validation before broad use.
- **Batch semantics:** a batch now reports partial failure, but it is not
  transactional. Add a preflight phase and an optional undo-group rollback
  mode before using batches for destructive scene changes.

### Important Limits

- The Visual Scripting generator and validator are informed by the captured
  Banter node data, but do not prove that a generated graph loads and executes
  in a target SDK/version. Add a Unity import-and-open test scene for graph
  fixtures.
- State export only covers the active scene and stops hierarchy recursion at
  depth 10. Additive scenes and deeper hierarchies are not represented fully.
- Prefab scanning is synchronous and exports at most 500 prefabs per category.
  Large projects should move to incremental scanning and expose paging.
- Import status is editor-global rather than a reliable per-asset compiler
  diagnostic. It should be backed by AssetPostprocessor events and structured
  compilation diagnostics.
- The launcher still defaults to `C:/tools/banter-mcp`. That is correct for
  this workstation, but a distributable installer should bundle or discover a
  versioned server location rather than rely on a machine-specific source path.
